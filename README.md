## 一、这是什么

一个**离线优先**的通讯录网页。它不需要服务器、不需要安装、不需要构建 —— 双击 `contact-address-book.html` 就能用。

数据默认存在浏览器本地（localStorage），如果你愿意花 3 分钟配置 Supabase，数据就会同步到云端，手机、平板、电脑打开都是同一份通讯录。

**核心设计取向：**

| 取向 | 说明 |
|---|---|
| 单文件 | 整个应用（HTML + CSS + JS）就是一个 `.html` 文件，可直接邮件发送、U 盘拷贝、托管到任意静态空间 |
| 离线可用 | 断网也能查看、搜索、导入导出；连不上 Supabase 会自动退回「本地模式」，不报错、不白屏 |
| 双模式 | 有云用云，无云用本地。两种模式的功能完全一致 |
| 只读访客 | 把链接发给别人，对方只能查看和搜索，改不了任何数据 |
| 标准格式 | 导入导出严格遵循 vCard RFC 2426 / RFC 6350，苹果通讯录、安卓通讯录、Outlook 都能互通 |

## 二、功能总览

### 联系人

- 新增 / 编辑 / 删除联系人
- **逐字段编辑**：姓名 7 项、电话 4 项、邮箱网站 3 项、单位 3 项、地址 5 项、生日 / 备注 / 头像 / 星标
- 头像 URL、生日（支持 `1990-01-01` 或 `--01-01` 只记月日）、备注多行文本
- 联系人卡片：列表只显示**姓名 + 电话**，点击弹出详情卡片展示**全部字段**

### 分类

- **两级分类**：一级分类（如「家人」）+ 二级分类（如「直系」「亲戚」）
- 分类可**增加 / 编辑 / 删除**（改名、换图标、调整顺序）
- 侧栏分类支持**折叠 / 展开**，分类很多时列表**独立滚动**
- 二级分类多于一屏时可单独滚动

### 标签

- 标签可增加 / 编辑 / 删除
- 支持批量给多个联系人打标签
- 标签云支持折叠与滚动

### 搜索

- **模糊匹配**：搜「138」能命中 `13800001234`，搜「张」能命中的所有姓张的
- 搜索范围覆盖：姓名、昵称、全部电话、邮箱、公司、职位、地址、标签、备注
- 电话号码**忽略格式差异**：`138 0000 1234`、`138-0000-1234`、`+8613800001234` 都能互相搜到

### 导入 / 导出

- 格式：**vCard 2.1 / 3.0 / 4.0**、CSV、JSON、TXT
- 范围：单条 / 勾选多条 / 当前分类整类 / 全部
- 导入时可**指定落到哪个一级分类 + 二级分类**
- 提供 **4 种可下载模板**

### 批量操作

- 多选模式：全选当前 / 取消选择 / 反选
- 批量导出所选、批量打标签、批量改分类、批量删除

### 其他

- 🌙 深色 / 浅色主题切换（记忆偏好）
- 📱 响应式：桌面三栏，手机抽屉式侧栏
- 🔐 管理员密码解锁编辑权限
- ♻️ 导入去重、字段智能识别、容错解析

### 方式 A：本地直接打开（最快）

1. 下载 `contact-address-book.html`
2. 双击打开（Chrome / Edge 均可）
3. 点右上角 **⚙️ 设置** → 「数据库」页签 → 点「载入示例数据」就能看到效果

## 六、导入与导出

### 导出

1. 点工具栏 **📤 导出**
2. 选**范围**：
   - 全部联系人
   - 当前分类 / 当前标签下的联系人
   - 多选模式下已勾选的联系人
   - 单条（详情卡片里的导出按钮）
3. 选**格式**：vCard 2.1 / 3.0 / 4.0、CSV、JSON
4. 下载

> 导出多个联系人时，vCard 文件里会有多个 `BEGIN:VCARD`…`END:VCARD` 块，这是标准做法，直接扔进手机通讯录就能批量导入。

### 导入

1. 点工具栏 **📥 导入**
2. 选择文件（支持 `.vcf` `.vcard` `.csv` `.txt` `.json`，可多选）
3. 选**目标分类**：一级分类 +（可选）二级分类
4. 预览解析结果，确认后导入

**容错能力：**

- 自动识别分隔符（逗号 / 分号 / 制表符）
- 表头智能映射（中英文都认：`手机` = `phone_mobile` = `mobile` = `cell`）
- vCard 折行自动拼接
- 2.1 的 `QUOTED-PRINTABLE` 中文编码自动解码
- 重复联系人（姓名 + 手机都相同）会提示是否跳过

## 八、vCard 2.1 / 3.0 / 4.0 说明

> 应用内「设置 → 关于」页签有一份**可折叠的完整字段参考**，包含三个版本全部字段的写法、格式要求和 8 条常见坑。下面是要点摘录。

### 版本速览

| | vCard 2.1 | vCard 3.0 | vCard 4.0 |
|---|---|---|---|
| 发布年份 | 1996 | 2004 | 2011 |
| 规范 | vCard 2.1 | RFC 2426 | RFC 6350 |
| 电话写法 | `TEL;CELL:13800001234` | `TEL;TYPE=CELL:13800001234` | **同 3.0** |
| 地址写法 | `ADR;HOME:;;街道;城市;省;;邮编;国家` | `ADR;TYPE=HOME:;;街道;城市;省;;邮编;国家` | **同 3.0** |
| 多类型分隔 | **分号** `TEL;CELL;VOICE:` | **逗号** `TEL;TYPE=CELL,VOICE:` | 同 3.0 |
| 编码 | 需 `ENCODING=QUOTED-PRINTABLE` 传中文 | UTF-8 | UTF-8（原生） |
| 头像 | `PHOTO;ENCODING=BASE64;TYPE=JPEG:` | `PHOTO;ENCODING=b;TYPE=JPEG:` | `PHOTO:data:image/jpeg;base64,` |
| 兼容性 | 老设备 | **最广** ⭐ | 新设备 |

**不知道选哪个 → 用 3.0。** 它是兼容性最好的版本，苹果、安卓、Outlook、Gmail 全部支持。

### ⚠️ 最容易踩的坑

**1. URI 型的取值不转义冒号**

`URL` 和 `PHOTO;VALUE=uri` 的值是 **URI 类型**，不是文本类型：

```
❌ 错误： URL:https\://example.com
✅ 正确： URL:https://example.com
```

vCard 2.1 里「把 `:` 转义成 `\:`」这条规则**只针对文本型取值**（`N` / `FN` / `ORG` / `ADR` / `NOTE` / `TITLE`）。写成 `https\://` 后，手机和邮件客户端**认不出这是个链接**。

**2. 换行必须是 CRLF**

vCard 规范要求 `\r\n`，不是 `\n`。本应用导出时严格遵守。

**3. 单行不超过 75 字节**

超过要折行：续行以**一个空格**开头。注意是**字节**不是字符 —— 一个中文字符是 3 字节。本应用导出时按字节计算，不会把多字节字符劈成两半。

**4. 全角冒号 `：` 是普通文本，不转义**

只有半角 `:`（U+003A）才需要处理，全角 `：`（U+FF1A）原样保留。

## 十三、技术栈与结构

### 技术栈

- **纯原生**：HTML5 + CSS3 + 原生 JavaScript（ES2020+）
- **零依赖**：没有框架、没有构建工具、没有 npm
- **零后端**：数据直接走 Supabase REST API（PostgREST）
- 单文件交付：`contact-address-book.html`

### 关键实现

| 主题 | 做法 |
|---|---|
| vCard 解析 | 手写状态机解析器，逐行扫描，支持折行还原、QUOTED-PRINTABLE 解码、类型参数识别 |
| vCard 生成 | `toVCard()` 按版本分支，`vEsc()` 处理文本转义，`vEscUri()` 处理 URI 型取值（不转义冒号） |
| 折行 | 按**字节**计数 75 上限，UTF-8 多字节字符不劈开 |
| 中文编码 | vCard 2.1 导出中文时用 `ENCODING=QUOTED-PRINTABLE` |
| 云同步 | `fetch` 调 PostgREST，`apikey` + `Authorization: Bearer` 头，`Prefer: return=representation` |
| 去重 | 姓名规范化 + 电话号码去掉非数字后比对 |
| 搜索 | 全部字段拼接后做子串匹配；电话字段额外做「纯数字」匹配 |
| 容错启动 | `bootFirstPaint()` 逐步 try/catch，单个渲染函数失败不影响其他 |

## 十四、常见问题 FAQ

**Q1：双击打开后是白屏 / 没有数据？**
正常。首次打开数据库是空的。点 ⚙️ 设置 → 数据库 → 「载入示例数据」看看效果。

**Q2：换电脑后数据不见了？**
本地模式的数据只存在那台电脑的那个浏览器里。有两条路：① 配 Supabase 云同步；② 在原电脑「导出 → vCard」再在新电脑导入。

**Q3：手机和电脑怎么同步？**
必须配 Supabase。两边填同一个 Project URL + Key，就自动同步了。

**Q4：显示「本地模式」，连不上 Supabase？**
按顺序排查：
1. 设置里的 Project URL 和 Key 填对了吗（Key 应该是 `sb_publishable_...` 开头）
2. SQL Editor 里的建表脚本执行成功了吗
3. 网络是否能访问 `*.supabase.co`（部分网络环境需要代理）
4. 点「测试连接」看具体报错信息

**Q5：管理员密码忘了？**
- 云端模式：在 Supabase SQL Editor 执行
  ```sql
  delete from app_settings where key = 'admin_password_hash';
  ```
  然后重新打开应用，会恢复默认密码 `02468#abAB`。
- 本地模式：浏览器控制台执行 `localStorage.removeItem('contacts.admin.hash')`。

**Q6：导入 vCard 中文乱码？**
确认文件是 UTF-8 编码。vCard 2.1 的老文件可能是 GBK，用记事本另存为 UTF-8 再导入。

**Q7：导入后有些字段丢了？**
检查表头名称。本应用认中英文别名（如 `手机` / `mobile` / `cell` / `phone_mobile` 都认），但完全自定义的列名认不出。用「下载模板」照着填最稳。

**Q8：能把链接发给别人看吗？**
可以，访客只有查看和搜索权限。**但请注意**：如果把 Supabase 配好了，**数据是公开可读的**（匿名 key + RLS 允许 select）。所以别放敏感信息。详见[第九节权限模型](#九权限模型)。

**Q9：导出到手机后联系人重复了？**
手机通讯录在导入时通常按「姓名+电话」判断是否已存在。如果还是重复，可能是同一个人存了多个电话格式（如 `13800001234` 和 `+8613800001234`），手机认成两个人了。

**Q10：支持多少个联系人？**
Supabase 免费版 500 MB，按每条联系人 1 KB 估算，约 **50 万条**。浏览器 localStorage 上限通常 5–10 MB，本地模式约 **5000–10000 条**。

**Q11：分类太多侧栏很长怎么办？**
点「全部折叠」，或者点单个分类左侧的小三角折叠它下面的二级分类。侧栏会自动出现滚动条。二级分类超过 8 个的分类默认就是折叠的。
